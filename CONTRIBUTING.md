# Contributing to NITM-SOSC

First of all, thank you for considering contributing to NITM-SOSC.

We believe open source is built through curiosity, collaboration and the willingness to learn from one another.

You don't need to be an expert to contribute. Whether you're writing code, improving documentation, identifying bugs, sharing resources or proposing ideas, your contribution matters.

**Learn Independently. Build Collaboratively. Contribute Globally.**

---

## 01 / Who Can Contribute?

NITM-SOSC is an independent, student-led open-source community originating at the National Institute of Technology Manipur.

Our initial community is intended for NIT Manipur students across all departments, academic years and technical backgrounds.

We welcome contributions from:

- Beginners exploring programming and technology.
- Developers building personal or collaborative projects.
- Students interested in artificial intelligence and machine learning.
- Cybersecurity and systems enthusiasts.
- Designers, researchers and technical writers.
- Anyone interested in learning and contributing to open source.

You don't need previous open-source experience.

---

## 02 / Ways to Contribute

There are several ways to participate in NITM-SOSC.

### Code Contributions

- Develop new features.
- Fix existing bugs.
- Improve performance and reliability.
- Write automated tests.
- Refactor and improve existing implementations.

### Documentation

- Improve README files.
- Write installation guides.
- Create technical tutorials.
- Correct errors and clarify explanations.

### Research and Learning

- Explore emerging technologies.
- Share technical discoveries.
- Publish useful learning resources.
- Document experiments and findings.

### Design and Creative Contributions

- Improve user interfaces.
- Create project assets and illustrations.
- Improve accessibility and user experience.

### Community Contributions

- Participate in technical discussions.
- Review pull requests.
- Report reproducible issues.
- Help newcomers.
- Propose and maintain collaborative projects.

## 03 / Find Something to Work On

Explore our [GitHub repositories](https://github.com/orgs/NITM-SOSC/repositories).

Look for issues labelled:

| Label | Meaning |
|---|---|
| `good first issue` | Suitable for beginners |
| `help wanted` | Additional contributors needed |
| `bug` | Something needs fixing |
| `enhancement` | An improvement is proposed |
| `documentation` | Documentation needs attention |

If you find something interesting:

1. Read the issue carefully.
2. Check whether someone is already working on it.
3. Ask questions if the requirements are unclear.
4. Comment on the issue to express your interest.
5. Wait for maintainer guidance when necessary.

For larger changes, discuss your proposal with the maintainers before beginning implementation.

## 04 / Development Workflow

We use the standard GitHub collaboration workflow.

### Step 1 — Fork

Fork the project repository into your personal GitHub account.

### Step 2 — Clone

Clone your fork locally:

```bash
git clone https://github.com/YOUR-USERNAME/REPOSITORY.git
cd REPOSITORY
```

### Step 3 — Create a branch

Create a separate branch for your contribution:

```bash
git checkout -b feature/your-feature
```

Examples:

```bash
git checkout -b fix/login-error
git checkout -b docs/update-readme
git checkout -b feature/add-search
```

### Step 4 — Make your changes

Follow the project's existing architecture, coding conventions and technical requirements.

Keep your changes focused and avoid unrelated modifications.

### Step 5 — Test

Test your changes wherever applicable.

Make sure existing functionality is not unintentionally broken.

### Step 6 — Commit

Write meaningful commit messages:

```bash
git add .
git commit -m "feat: add search functionality"
```

### Step 7 — Push

Push your branch to your fork:

```bash
git push origin feature/your-feature
```

### Step 8 — Open a Pull Request

Create a Pull Request against the original repository.

Explain:

- What you changed.
- Why the change is necessary.
- How you tested it.
- Which issue it addresses, if applicable.

Use the repository's Pull Request template when available.

## 05 / Code and Documentation Standards

We encourage contributors to maintain a consistent standard.

### Code

- Write readable and maintainable code.
- Follow the project's existing conventions.
- Use meaningful variable and function names.
- Avoid unnecessary dependencies.
- Include tests where appropriate.
- Document complex implementations.

### Documentation

- Use clear and understandable language.
- Keep examples accurate.
- Update documentation when functionality changes.
- Avoid unnecessary complexity.

### Security

- Never commit passwords, API keys or private credentials.
- Do not introduce malicious code.
- Respect software licences.
- Report vulnerabilities privately through the appropriate security reporting channel.

---

## 06 / Pull Request Review

Every contribution may undergo maintainer review.

Maintainers may:

- Request modifications.
- Ask technical questions.
- Suggest alternative implementations.
- Request additional tests.
- Approve and merge the contribution.

Please respond constructively to feedback.

A Pull Request is a collaborative process, not an individual evaluation.

Contributors should not merge their own Pull Requests unless explicitly authorised by the repository's maintainers.

---

## 07 / Communication

We encourage open, respectful and constructive communication.

Use GitHub Discussions for:

- Technical questions.
- Project proposals.
- Learning resources.
- Community announcements.
- General conversations.

Use GitHub Issues for:

- Bug reports.
- Feature requests.
- Defined project tasks.

Before creating a new issue or discussion, check whether a similar topic already exists.

---

## 08 / Project Ownership and Maintenance

Projects contributed to NITM-SOSC should have clear maintainers and documented responsibilities.

Contributors are encouraged to:

- Take responsibility for their contributions.
- Maintain the projects they initiate.
- Document important technical decisions.
- Respect existing maintainers.
- Communicate when they can no longer maintain a project.

Project maintainership and organisational governance are covered in our [Governance Policy](GOVERNANCE.md).

---

## 09 / Community Expectations

Every contributor is expected to:

- Respect other contributors.
- Welcome beginners.
- Give constructive feedback.
- Avoid harassment and discrimination.
- Respect intellectual property and software licences.
- Follow our [Code of Conduct](CODE_OF_CONDUCT.md).

We value collaboration over competition.

---

## 10 / Need Help?

If you are stuck or unsure where to begin:

- Visit [NITM-SOSC Discussions](https://github.com/orgs/NITM-SOSC/discussions).
- Explore our [GitHub repositories](https://github.com/orgs/NITM-SOSC/repositories).
- Ask questions in the relevant project discussions.
- Reach out to the project's maintainers.

No question is too basic when you're learning something new.
